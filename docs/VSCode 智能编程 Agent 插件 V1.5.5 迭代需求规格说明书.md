# VSCode 智能编程Agent插件 V1.5.5 迭代需求规格说明书

**基准版本**：V1.5.0 **迭代版本**：1.5.5 **需求类型**：联网搜索质量专项优化 + 结果呈现体验升级 + 质量安全保障 **核心目标**：针对性解决搜索召回精准度低、结果匹配度差的核心问题；将固定条数的结果策略升级为动态浮动机制，同步提升摘要信息密度；修正网页链接指向不准确的问题，实现结果条目与目标页面一一对应；所有优化严格限定于搜索模块内部，不侵入核心业务链路，确保存量功能零负向优化；交付物全程合规无隐私信息，全项目版本与文档统一。

------

## 一、联网搜索精准度与召回质量优化（P0 最高优先级）

### 问题背景

当前联网搜索功能存在查询词匹配度不足、召回结果相关性弱的问题，常出现偏离任务目标的无效搜索，无法为 Agent 提供有效信息支撑，搜索工具的实用价值未达预期。

### 需求描述

从查询生成、结果召回、质量校验三个环节全链路优化搜索精准度，参考业界成熟 Agent 搜索方案实现，确保搜索动作与任务目标高度对齐：

1. 查询词（Query）生成策略优化
   - 强化任务语义解析能力，Agent 生成搜索关键词前必须先提炼任务核心诉求，将模糊需求转化为精准、结构化的查询词，禁止使用宽泛、笼统的关键词发起搜索。
   - 针对技术类场景，强制补充技术栈、版本、报错关键词等限定信息，缩小召回范围，提升结果匹配度。
   - 单次搜索支持生成多组差异化查询词，用于互补召回，避免单一关键词导致的信息偏差。
2. 结果相关性重排序与过滤
   - 原始搜索结果返回后，新增二次相关性校验环节，基于任务目标对结果做语义匹配度打分，过滤低相关、广告、导航类、纯资讯类无效页面，仅保留高价值技术内容。
   - 优先排序官方文档、权威技术社区、开源仓库、专业技术博客等高信源结果，降低低质量内容的权重。
3. 多轮检索与自主纠错机制
   - 首次搜索结果质量不足时，Agent 可自主判断信息缺口，调整查询词后发起二次补充检索，直至获取足够有效信息，或判定无公开相关信息。
   - 严格控制单任务的搜索总轮次，避免无意义的反复搜索浪费时间与 Token。

### 验收标准

- 技术类任务的搜索结果与任务目标匹配度显著提升，无明显偏离主题的无效搜索结果；
- 报错、特定 API 用法等精准诉求可召回对应的高相关页面；
- 单次搜索信息不足时可自主调整关键词补充检索，无重复、无效的循环搜索；
- 搜索功能异常时仍不影响插件核心对话与执行能力，降级逻辑正常。

## 二、搜索结果呈现策略优化（P1 高优先级）

### 问题背景

当前固定 3-5 条结果的策略灵活性不足，简单任务条数冗余、复杂任务信息不足；同时摘要内容过于精简，关键信息缺失，且部分结果链接仅指向网站首页，无法直达目标页面，用户溯源查看成本高。

### 需求描述

1. 结果条数动态浮动机制
   - 取消固定 3-5 条的数量限制，改为 2-20 条的动态浮动区间，由 Agent 根据任务复杂度、结果相关性自主决定返回条数。
   - 简单明确的查询，保留 2-5 条高相关结果即可；复杂、多维度的信息查询，可扩展至最多 20 条结果；单轮信息不足时优先通过二次搜索补充，而非单轮无限制扩容。
   - 结果数量变化不改变对话流内的区块展示规范，长列表支持区块内二级滚动，不撑高对话面板。
2. 摘要信息密度提升
   - 优化网页摘要提取粒度，在控制 Token 开销的前提下，保留核心技术细节，包括关键参数、代码片段、方案步骤、版本说明等任务强相关信息，避免过度压缩导致信息失真。
   - 摘要采用结构化呈现，保留段落层级，避免内容堆砌，兼顾信息完整性与可读性。
   - 仍严格执行三级过滤压缩机制，禁止全量原始网页内容直接注入上下文，Token 开销可控。
3. 目标链接准确性修正
   - 每条搜索结果必须绑定对应目标页面的完整直达 URL，确保链接可直接跳转至内容详情页，禁止仅指向网站域名、首页或频道页。
   - 对话流内展示的结果标题、来源均为可点击超链接，点击后直接在默认浏览器打开对应详情页面。
   - 新增链接有效性前置校验，过滤死链、重定向链、无效跳转链接，确保用户点击可直达目标内容。

### 验收标准

- 搜索结果条数随任务复杂度动态调整，简单任务无冗余条目，复杂任务信息覆盖充分；
- 摘要包含足够的关键技术信息，可支撑 Agent 完成对应任务，无过度精简导致的信息缺失；
- 所有结果链接均可直达对应详情页面，无首页、域名级别的错误跳转；
- 单轮搜索的 Token 开销仍处于合理范围，无脑注入上下文的问题。

## 三、代码审查与全量功能回归校验（P0 必做）

### 问题背景

搜索模块内部逻辑调整涉及查询生成、结果处理、交互展示多个子环节，需通过代码审查与全量回归确保修改不向外扩散，严格杜绝负向优化，同时保障交付物隐私安全。

### 需求描述

1. 专项代码审查

   - 逻辑边界审查：确认所有优化均封装在搜索模块内部，未修改 Agent 核心调度、消息协议、权限体系等存量链路，无耦合侵入。
   - 异常安全审查：确认动态条数、摘要提取、链接校验等新增逻辑均有异常兜底，无边界 case 导致的崩溃、报错。
   - 隐私安全审计：全项目与最终打包产物 `.vsix` 全面排查，确认无任何硬编码 API 密钥、私人联系方式等隐私信息；作者署名 `wangh` 正常保留，不属于隐私范畴。
   - Token 安全审查：确认动态条数扩容后仍有严格的上限控制与摘要压缩，无 Token 失控风险。

2. 全量功能回归测试

   覆盖所有存量核心功能，范围包括但不限于：

   - 文本对话、多模态输入、智能体模式完整执行链路
   - 多服务商切换、模型切换、全局配置管理
   - 上下文 Token 统计、自动/手动压缩机制
   - 历史会话读写、续接、删除管理
   - 双层权限体系、安全模式切换逻辑
   - 编辑器文件修改高亮联动、右键代码注入
   - 思考链分层展示、对话滚动交互、区块折叠

### 验收标准

- 代码审查无架构耦合、逻辑漏洞与安全风险；
- 交付物无任何隐私信息，作者署名正常保留；
- 存量核心功能零回归，体验与 V1.5.0 版本完全一致。
