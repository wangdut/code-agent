# VSCode 智能编程Agent插件 V0.6.0 迭代需求规格说明书

**基准版本**：V0.5.1

 **迭代版本**：0.6.0 

**需求类型**：交互范式重构 + 数据实时性优化 + 编辑器可视化体验修复 **核心目标**：对齐业界主流 Agent 插件的流式分步输出范式，提升 Token 统计与用量数据的实时性与准确性，修复编辑器高亮联动的样式与交互缺陷，整体保留现有视觉与功能风格。

------

## 一、核心交互范式重构：流式分步执行输出（P0 最高优先级）

### 问题背景

当前插件采用分块集中式输出：整段思考过程集中在单个思考区块完整输出后，再统一展示工具调用与执行结果，所有执行步骤聚合在单一执行块内。该模式下用户无法感知 Agent 分步执行的节奏与链路，无法实时追踪每一步动作，不符合 Qoder 等主流插件的流式分步交互范式，排查与观察成本高。

### 需求描述

重构对话流渲染与消息推送逻辑，采用**时序化流式分步输出**范式，思考、工具调用、执行结果按实际执行顺序逐段交替输出，还原完整执行链路：

1. **思考过程分段流式输出**：推理过程中每生成一段完整语义的思考内容，即时渲染至对话流中，不等待整轮思考全部结束再统一展示；思考内容随执行推进持续追加，与后续动作自然衔接。
2. **工具节点即时插入**：解析到工具调用指令后，立即在对话流对应位置插入工具执行节点并展示加载状态，无需等待当前思考段落结束；支持「思考→调用工具→返回结果→继续思考→调用下一工具」的自然交替节奏。
3. **执行结果即时呈现**：文件读写、终端命令等工具执行完成后，结果即时追加到对应工具节点下，与思考内容形成完整的分步动作链路。
4. **结构保留与折叠能力**：执行完成后对话流保留完整的分步时序结构，不合并为单一大块；思考区块仍支持展开/折叠切换，默认展开以展示完整执行链路。

### 验收标准

- 执行多步任务时，思考、读文件、终端执行、写文件、总结等动作按实际执行时序交替出现，无集中分块输出现象；
- 每一步动作均有即时视觉反馈，无长时间无内容更新的等待状态；
- 任务结束后对话流保留清晰的分步执行链路，可回溯每一步操作与对应思考；
- 思考区块的折叠功能正常可用，不影响分步结构。

## 二、Token 统计与用量数据实时性优化（P1 高优先级）

### 问题背景

当前上下文 Token 占用仅在整轮推理结束后更新，刷新频率低，无法实时反映会话窗口的实际消耗进度；今日用量、账户余额与 API 调用次数数据更新不及时，数值准确性不足，无法为用户提供可靠的用量参考。

### 需求描述

1. 上下文 Token 实时统计
   - 改写 Token 统计触发时机：每接收一段流式输出片段（思考内容、正式回复、工具结果）后，立即重新计算当前会话完整消息链的总 Token 占用，并同步更新面板顶部的进度条与数值展示。
   - 统计口径保持与目标模型分词规则一致，覆盖系统提示、历史对话、已输出内容、待输入内容全量范围。
2. 用量与余额数据准确性优化
   - 今日 Token 用量、API 调用次数随每次接口响应实时累加，数值与接口返回的计费数据对齐，杜绝统计滞后。
   - 账户余额查询功能支持手动触发刷新，点击后重新请求模型官方用量接口，同步返回最新账户余额、周期内已用金额、累计调用次数等全量字段。
   - 所有用量字段严格映射官方 API 返回参数，确保展示数值与服务商控制台数据一致。

### 验收标准

- 对话输出过程中，上下文占用数值随内容输出实时更新，无整轮结束才刷新的滞后现象；
- 今日用量、调用次数随每次 API 调用实时累加，数值准确无偏差；
- 手动点击查询余额可获取最新数据，余额、已用金额等字段与官方控制台一致。

## 三、编辑器文件修改高亮联动优化（P1 高优先级）

### 问题背景

当前新增行高亮带有多余外轮廓线，视觉效果冗余粗糙；通过插件对话框「跳转编辑器」按钮打开的文件，无法立即展示变更高亮标记，需关闭重开才生效；标记的刷新与清除逻辑不符合使用预期。

### 需求描述

1. 高亮样式精简优化
   - 基于 VSCode `TextEditorDecorationType` 调整装饰样式：新增行仅保留左侧绿色竖线 + 浅绿色行背景，移除所有外边框、轮廓线效果；删除行保留左侧红色竖线 + 浅红色行背景，整体风格简洁克制，对齐 VSCode 原生 Diff 视觉体验。
2. 跳转联动即时生效
   - 点击对话框内文件变更节点的「跳转编辑器」按钮打开目标文件时，自动为该编辑器实例应用对应变更的高亮装饰，确保文件打开即可直观看到增删行标记，无需关闭后重新打开。
3. 标记生命周期规范化
   - 同一文件被 Agent 再次执行修改操作时，自动清除旧的变更装饰，刷新为最新一次修改的高亮结果，始终展示当前最新变更。
   - 用户手动关闭目标文件后再重新打开时，变更高亮标记自动清除，不永久残留污染编辑器视图。

### 验收标准

- 新增行无任何外轮廓/边框效果，仅左侧竖线与行背景高亮，样式整洁；
- 通过对话框跳转打开的文件，立即正确显示增删行高亮标记；
- 文件二次修改后，高亮自动更新为最新变更；关闭重开后标记自动清除，无残留。
