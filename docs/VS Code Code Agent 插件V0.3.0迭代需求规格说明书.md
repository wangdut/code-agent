# VSCode 智能编程Agent插件 V0.3.0 迭代需求规格说明书
**基准版本**：V0.2.0
**迭代版本**：0.3.0
**需求类型**：核心数据缺陷修复 + 编辑器联动能力增强 + 交互体验优化 + 效能专项分析
**核心目标**：修复 Token 统计、用量显示等核心数据错误，补齐编辑器可视化联动能力，优化交互操作效率，输出执行效能优化方案，整体保留现有视觉与交互风格。

## 一、核心缺陷修复（P0 最高优先级，本迭代必须闭环）
### 1.1 上下文窗口 Token 统计逻辑修正
**问题背景**：当前面板顶部的「上下文占用」数值错误引用了本地会话快照文件的磁盘大小（字节数），并非模型实际上下文窗口的 Token 占用量，数据口径完全错误，无法指导用户判断上下文余量。
**需求描述**：
1. 彻底移除基于本地文件磁盘大小的错误统计逻辑，重新实现基于模型 Token 规则的真实计数能力。
2. 明确统一统计口径：
   - 统计范围：当前会话完整消息链，包含系统提示词、历史对话、工具调用结果、用户待输入内容，与实际发送给模型的请求体完全一致。
   - 统计依据：采用与当前所选模型匹配的分词规则（Tokenizer）计算 Token 数量，确保数值与模型侧实际窗口占用、计费口径一致。
   - 展示分母：绑定当前选中模型的官方总上下文窗口大小，随模型切换同步更新。
3. 展示规范：
   - 主展示格式为 `已用 X.XK / 总窗口 Y.YK`，单位统一为千 Token，保留 1 位小数。
   - 旁注当前模型的单轮最大输出 Token 限制，辅助用户理解生成长度边界。
   - 自动压缩阈值进度条同步基于真实 Token 数值计算。
4. 统计时机：每次发送消息、接收模型回复、执行上下文压缩、切换模型后实时刷新数值。
**验收标准**：
- 上下文占用数值与模型实际接收的 Token 量级一致，不再与文件大小挂钩；
- 切换不同模型时，分母与计数规则同步适配；
- 自动压缩触发阈值与展示数值匹配准确。

### 1.2 账户已用金额统计修复
**问题背景**：设置页账户余额展示中，括号内的「已用金额」恒为 0.00，未正确读取模型服务商的用量数据，属于字段映射错误。
**需求描述**：
1. 修正 DeepSeek 等已适配模型的用量查询接口解析逻辑，正确映射「周期内已消费金额」字段，不再硬编码为 0。
2. 明确统计周期为自然日，与当日 Token 用量统计口径保持一致。
3. 保留原有展示格式 `余额 X.XX CNY（已用 Y.YY CNY）`，确保数值实时、准确更新。
4. 新增异常兜底：接口请求失败或权限不足时，展示「查询失败」提示，不展示错误数值。
**验收标准**：
- 已用金额可随 API 调用消耗正常累加，数值与官方控制台一致；
- 余额与已用金额字段区分清晰，无混淆；
- 异常场景下无错误数值展示。


### 1.3 历史会话持久化加载异常修复
**问题背景**：会话数据已持久化存储至工作区 `.code-agent/history` 目录的 JSON 文件中，但 VSCode 重启、插件重新激活后，历史会话侧边栏未正确扫描加载本地已存会话文件，列表展示为「暂无历史会话」，导致历史会话回溯与续接能力完全失效。
**需求描述**：
1. 重构插件激活与会话管理模块的初始化时序，在插件激活完成、侧边栏 WebView 就绪后，强制执行一次本地历史目录的全量扫描与元数据加载流程，确保启动即完成历史会话列表渲染。
2. 优化历史文件扫描与解析逻辑：
   - 严格匹配会话文件命名规则，自动过滤 `audit-log.jsonl`、`usage-log.json` 等非会话日志文件，避免解析异常中断加载流程；
   - 按文件最后修改时间倒序排列会话列表，与新建会话的排序逻辑保持一致；
   - 启动阶段仅解析每个会话文件的元数据（会话标题、创建时间、最后活跃时间、消息条数）用于列表展示，不全量加载会话正文，降低启动 IO 与内存开销。
3. 新增异常兜底机制：单个会话文件损坏、解析失败时，记录错误日志并跳过该文件，其余合法会话正常加载，禁止单文件异常导致整个列表为空。
4. 补充目录变更监听能力：历史目录下新增、删除、重命名会话文件时，侧边栏列表实时同步更新，保证文件系统状态与 UI 展示一致。
5. 会话续接逻辑保持兼容：点击历史会话条目时，按需读取对应文件的完整内容，恢复对话上下文与执行状态，支持正常续聊。
**验收标准**：
- VSCode 关闭重启后，侧边栏可正确展示所有本地已存会话，无遗漏、无缺失；
- 日志类文件不会被误识别为历史会话，列表展示准确；
- 单个会话文件损坏不影响整体列表加载，异常有本地日志可追溯；
- 打开历史会话可完整恢复上下文，续聊功能与关闭前表现一致。

## 二、功能与体验增强（P1 高优先级）
### 2.1 思考过程语言自适应
**问题背景**：Agent 推理思考内容固定为英文输出，与用户输入语言不一致，提升了中文用户的阅读成本。
**需求描述**：
1. 实现思考输出语言跟随用户输入动态适配：用户使用中文提问时，思考过程默认输出中文；用户使用英文提问时，自动切换为英文。
2. 在系统提示词与推理指令中增加明确的语言约束：要求思考过程必须使用与用户最近一次输入相同的自然语言。
3. 代码片段、工具参数等非自然语言内容不受此规则限制，保持原有格式。
**验收标准**：
- 全中文对话场景下，思考过程 100% 为中文输出；
- 中英文混合输入时，以用户主导语言为准；
- 代码、命令等技术内容格式不受影响。

### 2.2 编辑器文件修改实时高亮联动
**问题背景**：当前文件修改的 diff 仅在插件对话框内展示，需用户反复切换面板对比，且全量展示文件内容导致对话框信息冗余；需对齐 Qoder 交互范式，将修改可视化迁移到编辑器原生区域。
**需求描述**：
1. **编辑器侧 diff 装饰**：
   - Agent 执行文件写入/编辑操作时，自动在 VSCode 编辑器中打开目标文件（未打开则自动唤起）。
   - 基于 VSCode 原生 `TextEditorDecorationType` API 对变更行做可视化标记：新增行左侧绿色竖线+浅绿行背景，删除行左侧红色竖线+浅红行背景。
   - 装饰仅为视觉标记，不修改文件原始内容，关闭文件后自动清除，不污染用户工作区。
2. **对话框侧精简展示**：
   - 对话流中的文件操作节点，不再全量展示文件完整内容，仅展示文件名、变更行统计：`+N 新增`（绿色）、`-N 删除`（红色）。
   - 点击该统计节点可直接跳转至编辑器对应文件的修改位置，实现双向联动。
3. 多文件修改时，按文件维度分别展示统计，保持对话框整洁，提升信息密度。
**验收标准**：
- 文件修改后，编辑器内可直观看到增删行的颜色标记；
- 对话框内仅展示统计信息，无冗余全文内容；
- 点击对话框节点可精准跳转至对应文件修改处；
- 装饰不修改文件本体，关闭文件后无残留。

### 2.3 编辑器右键选中代码注入对话
**问题背景**：当前仅支持 @ 引用完整文件，无法快速针对局部代码片段提问，用户需手动复制代码到输入框，操作路径长。
**需求描述**：
1. 在 VSCode 编辑器右键上下文菜单（`editor/context`）中注册「Add to Code Agent」菜单项，仅当存在活跃文本选区时显示。
2. 点击菜单项后：
   - 自动向当前激活的对话输入框注入引用标签，格式为 `@[文件名] 行号范围: 起始行-结束行`（示例：`@[test.py] 28-89`）。
   - 对应行号范围内的代码片段同步加载至会话上下文，与现有 @ 全文件引用复用同一套上下文管理机制。
3. 输入框内的引用标签支持一键删除，与现有 @ 文件功能体验保持一致。
4. 支持单文件连续选中多段代码注入，自动合并或分别展示。
**验收标准**：
- 选中文本后右键可见对应菜单项，无选中时不显示；
- 点击后输入框正确展示文件与行号引用，代码片段正确注入上下文；
- 引用可正常删除，不残留无效上下文。

### 2.4 会话侧边栏点击外部自动收起
**问题背景**：展开会话列表侧边栏后，必须点击右上角收起按钮才能关闭，操作路径长，不符合抽屉式面板的通用交互直觉。
**需求描述**：
1. 会话列表侧边栏处于展开状态时，鼠标点击对话主面板（非侧边栏区域）的任意空白或内容区域，自动触发侧边栏收起。
2. 交互例外：点击侧边栏内部元素、输入框、功能按钮等交互控件时，不触发收起逻辑。
3. 收起动画与原有收起按钮保持一致，过渡流畅无突兀感。
**验收标准**：
- 展开侧边栏后，点击对话主面板空白处可正常收起；
- 点击侧边栏内部、输入框等区域不误触发收起；
- 动画流畅，不影响后续输入操作。


### 2.5 工具调用最大轮次可配置化
**问题背景**：当前 Agent 最大工具调用轮次为硬编码固定值（20轮），复杂多步任务易触发轮次上限导致执行中断，用户无法根据任务复杂度与模型能力自主调整阈值。
**需求描述**：
1. 在全局设置页的「Agent 行为」配置分组中，新增「最大工具调用轮次」数值输入框，用于控制单轮任务中 Agent 可自主调度工具的最大次数。
2. 参数规则：
   - 取值范围：正整数，最小值 1，最大值 1000，默认值保持 20，兼容现有行为；
   - 输入校验：禁止输入非数字、负数与超出范围的数值，非法输入时自动回退为合法值并给出 tooltip 提示。
3. 生效规则：配置修改后即时生效，作用于所有新建与续接的会话，无需重启插件。
4. 提示文案优化：当触发轮次上限时，提示文案同步展示当前配置的上限值，并引导调整入口，示例：`已达到最大工具调用轮次（20），任务可能未完全完成，请检查结果。可在设置中调整「最大工具调用轮次」以支持更长任务链路。`
**验收标准**：
- 设置页可正常修改最大轮次数值，边界与格式校验生效；
- 修改后新启动的任务按新阈值执行，无缓存旧值问题；
- 触发上限时提示文案准确，配置入口引导清晰。

## 三、执行效能专项分析（P2 仅方案输出，不修改代码）
### 3.1 执行速度偏慢的原因分析
针对「同任务比其他 Agent 插件慢」的问题，从架构链路层面定位核心耗时点，主要包含以下维度：
1. **串行工具调度**：当前每轮推理仅执行 1 个工具调用，多步操作（如读取多文件、连续修改）需多轮模型往返，网络与推理耗时线性叠加。
2. **全量上下文重传**：每轮请求携带完整历史消息链，长会话下 Token 体量大，传输耗时与模型推理耗时同步上升。
3. **执行时序串行**：需等待完整思考内容输出后，再解析工具指令并执行，思考生成与工具执行无并行空间。
4. **渲染层全量重绘**：长对话下每次消息更新触发全量 DOM 重绘，放大了卡顿感知。

### 3.2 不损失代码能力的优化方案
以下优化均不改变模型推理逻辑与工具执行规则，仅通过调度与架构优化压缩耗时，不影响代码生成质量：
1. **并行工具调用**：支持同批次无依赖的工具指令并行执行（如同时读取多个文件、同时查询目录结构），减少多轮往返次数。
2. **流式执行流水线**：思考内容流式输出过程中，提前解析工具调用指令，预启动工具执行，实现「推理+执行」并行，缩短总等待时长。
3. **上下文动态裁剪**：对非关键历史工具输出做轻量化降级，控制单轮请求 Token 体量，加快模型推理速度，同时不丢失核心任务信息。
4. **渲染层增量更新**：对话内容采用增量渲染，仅更新新增区块，避免长会话下全量重绘带来的界面卡顿。

### 3.3 落地说明
本迭代仅输出上述分析与优化方案，不修改 Agent 核心执行逻辑，待你确认方案后，再纳入下一轮迭代进行代码落地与效果验证。
