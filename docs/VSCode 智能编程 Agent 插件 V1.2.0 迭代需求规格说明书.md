# VSCode 智能编程Agent插件 V1.2.0 迭代需求规格说明书

**基准版本**：V1.1.0 

**迭代版本**：1.2.0 

**需求类型**：多模型接入体系缺陷修复 + 密钥安全加固 + 预置服务商体系落地 

**核心目标**：修复自定义服务商新增失败、密钥清除失效等阻断性功能缺陷；落地 API 密钥的系统级安全存储规范，杜绝敏感信息泄露风险；构建主流厂商预置配置与兜底模型列表体系，优化新增服务商的交互效率；所有修改严格限定于模型配置与接入层，不改动插件对话、Agent 执行、交互体验等存量成熟功能，确保零负向优化。

------

## 一、核心阻断性缺陷修复（P0 最高优先级，本迭代必须闭环）

### 1.1 自定义服务商新增失败问题修复

**问题背景**：当前新增自定义模型服务商时，系统返回「服务商不存在」错误，仅默认预置的 DeepSeek 可正常使用，自定义 OpenAI 兼容接口无法接入。根因为新增逻辑残留服务商白名单校验机制，未对自定义配置开放完整的新增与模型拉取链路，导致动态接入能力未实际生效。

**需求描述**：

1. 移除新增服务商环节的服务商白名单校验逻辑，开放全量自定义接入能力，所有符合 OpenAI 兼容协议的接口均可通过填写 Base URL 完成新增。
2. 重构服务商新增与模型拉取流程：用户提交服务商配置后，基于填写的 Base URL 调用标准 `/models` 接口执行模型列表拉取，拉取成功则完成服务商创建与模型入库；拉取失败则返回明确的错误原因（如网络异常、接口不兼容、鉴权失败），不再笼统提示服务商不存在。
3. 保留 DeepSeek 为默认预置服务商，维持「预置服务商不可删除、支持编辑名称与 Base URL」的现有规则不变。

**验收标准**：

- 填写任意合规的 OpenAI 兼容格式 Base URL，均可成功完成服务商新增，无「服务商不存在」的错误拦截；
- 新增成功后自动拉取对应服务商的模型列表，可正常切换模型并发起对话；
- 预置 DeepSeek 服务商保留不可删除规则，编辑功能正常可用；
- 拉取失败时返回精准错误提示，可定位问题原因。

### 1.2 服务商密钥清除功能修复

**问题背景**：编辑预置/自定义服务商时，勾选「清除已配置的密钥」选项并保存后，密钥未被实际删除，插件仍可正常调用模型接口，清除操作无效，存在敏感信息残留风险。

**需求描述**：

1. 重构服务商编辑的保存逻辑，新增密钥清除的专属处理分支：勾选清除选项并确认保存后，立即从存储介质中彻底删除对应服务商的 API 密钥，无残留缓存。
2. 密钥清除后，调用该服务商下模型时统一拦截请求，弹出「未配置 API 密钥」的提示，引导用户前往设置页补充，确保清除操作真实生效。
3. 密钥清除操作仅作用于当前服务商，不影响其他服务商的密钥配置。

**验收标准**：

- 勾选清除密钥并保存后，对应服务商的密钥被彻底删除，无法再正常调用模型接口；
- 清除密钥后有明确的状态提示，调用模型时有合规的拦截引导；
- 单服务商密钥清除不影响其他服务商的正常使用。

### 1.3 API 密钥安全存储规范落地

**问题背景**：需明确 API 密钥的存储安全边界，避免敏感信息写入项目文件、历史会话或打包产物，保障用户密钥隐私安全。

**需求描述**：

1. 全量密钥存储统一迁移至 VSCode 原生 `SecretStorage` 系统密钥库，所有服务商的 API 密钥仅存放于系统级安全存储区域，与插件配置文件、工作区数据完全隔离。
2. 严格执行敏感信息落盘禁令：插件所有持久化文件（含配置文件、历史会话 JSON、操作日志、审计日志）中，禁止写入任何明文或加密形式的 API 密钥，仅可存储服务商唯一标识、Base URL、模型元数据等非敏感信息。
3. 密钥仅在运行时内存中用于接口请求，不进入任何打包产物、不随项目文件同步、不写入工作区目录。
4. 完成改造后执行全量存储审计，排查所有本地持久化文件，确保无密钥泄露路径。

**验收标准**：

- 所有 API 密钥仅存储于 VSCode SecretStorage，工作区 `.code-agent` 目录、插件配置文件中无任何密钥相关信息；
- 插件重启后密钥可正常读取使用，不影响正常调用；
- 导出会话、分享配置等操作不会携带密钥信息。

## 二、预置服务商体系与模型列表兜底方案（P1 高优先级）

### 2.1 主流厂商配置与兜底模型预置

**问题背景**：多数 OpenAI 兼容厂商的 `/models` 接口需要鉴权，未填写 API 密钥时无法拉取模型列表，用户无法提前预览厂商支持的模型；同时手动填写各厂商 Base URL 操作成本高，易出错。

**需求描述**：

1. 预置国内外主流支持 OpenAI 兼容协议的模型服务商官方配置，包含服务商名称、官方标准 Base URL，作为用户新增时的快捷选项。预置范围覆盖国内主流厂商（DeepSeek、智谱AI、月之暗面、通义千问、字节跳动豆包等）与海外主流厂商（OpenAI、Anthropic 等），确保配置与官方最新接口对齐。
2. 所有预置服务商同步配套官方标准模型列表作为兜底数据，包含各厂商主流模型的名称、默认上下文窗口、最大输出 Token 等元数据，解决无密钥时无法拉取模型的问题。兜底数据随版本迭代更新，保障准确性。
3. 动态拉取优先级高于兜底数据：当用户配置密钥后，自动以接口拉取的最新模型列表为准，覆盖本地兜底数据，保证列表实时性。

### 2.2 新增服务商交互优化

**问题背景**：当前新增服务商仅支持纯手动输入，无快捷选项，配置效率低，易出现 URL 填写错误。

**需求描述**：

1. 将「新增模型服务商」弹窗中的服务商名称、Base URL 输入框升级为带下拉建议的复合输入框：
   - 点击输入框可展开预置服务商列表，选中对应厂商后自动填充名称与官方 Base URL；
   - 支持用户手动编辑、输入自定义内容，不强制使用预置选项，兼容私有化部署、自定义代理等场景。
2. API Key 输入框保持手动填写规则，不做预置，保留掩码显示与显隐切换能力。
3. 新增按钮保留「新增并拉取模型」交互，无密钥时点击新增则使用兜底模型列表完成创建，同时提示「未配置密钥，使用预置模型列表，配置密钥后可自动同步最新模型」。

**验收标准**：

- 新增弹窗可通过下拉快速选择预置厂商，自动填充正确的 Base URL；
- 支持手动输入自定义服务商名称与 Base URL，兼容非预置厂商接入；
- 无 API 密钥时可完成服务商新增，使用预置兜底模型列表；配置密钥后可自动拉取最新模型列表。

### 2.3 主界面模型下拉框服务商联动

**问题背景**：当前主界面模型下拉框未与服务商做关联，多服务商场景下模型列表混杂，切换逻辑不清晰，不符合「按服务商管理模型」的体系设计。

**需求描述**：

1. 对话底部快捷栏的模型切换下拉框，与当前生效的服务商绑定，仅展示当前选中服务商下的所有模型，不同服务商的模型分区展示、互不混杂。
2. 支持在设置页切换默认服务商，切换后主界面模型列表同步刷新；模型切换时，上下文统计、窗口阈值等参数同步适配对应模型的元数据，保证数据准确性。

**验收标准**：

- 主界面模型下拉框仅展示当前服务商的模型，列表清晰无混杂；
- 切换服务商后模型列表实时更新，无延迟、无残留其他服务商模型；
- 模型切换后上下文统计等参数同步适配，数值准确。

另外，注意，“设置”界面中的模型配置栏，默认模型这个条目要跟着模型供应商联动。

## 三、全量功能回归校验（P1 必做）

### 需求描述

完成上述所有修改后，对存量核心功能执行全量回归校验，确保所有修改仅作用于模型配置与接入层，不侵入业务功能逻辑。校验范围包括但不限于：

- 智能体模式完整执行链路、对话模式文件问答能力
- 上下文 Token 统计、自动/手动压缩功能
- 历史会话读写、续接、删除管理
- 编辑器高亮联动、右键代码注入
- 双层权限体系、安全模式切换
- 思考链分层展示、对话滚动交互、区块折叠

校验标准：所有功能表现与 V1.1.0 稳定版本完全一致，无功能失效、交互异常、样式错乱问题；发现关联缺陷同步修复闭环。

### 验收标准

- 存量核心功能零回归，体验与上一版本完全一致；
- 多模型相关修改不影响原有 DeepSeek 场景的正常使用。
