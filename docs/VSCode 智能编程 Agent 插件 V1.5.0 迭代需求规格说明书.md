## 一、联网搜索工具体系建设（P0 最高优先级）

### 1.1 全局功能开关配置

**问题背景**：需为联网搜索功能提供统一的全局控制入口，满足用户按需启停的需求，同时保持设置页交互风格与现有配置体系一致。

**需求描述**：

1. 在设置页「Agent 行为」配置分组中，新增「启用联网搜索」复选框开关，默认状态为勾选启用；UI 样式、排版间距与现有配置项完全统一，不破坏页面视觉一致性。
2. 开关为全局生效配置，关闭后 Agent 调度层完全屏蔽搜索工具，所有场景下均不会发起搜索请求，插件能力回退至 V1.4.5 版本状态。
3. 开关修改即时生效，无需重启插件。

**验收标准**：

- 设置页可正常勾选/取消联网搜索开关，样式与现有配置项风格统一；
- 关闭开关后，所有场景下 Agent 均不会调用搜索工具，功能完全回退至上一版本；
- 开关修改即时生效，无缓存延迟。

### 1.2 Agent 自主决策调度逻辑

**问题背景**：联网搜索为辅助能力，需由 Agent 根据任务语义自主判断调用时机，避免无效搜索浪费 Token 与执行耗时，同时不增加用户手动操作成本。

**需求描述**：

1. 将联网搜索作为标准工具纳入 Agent 工具调度体系，与文件读取、终端执行等工具同级，由 Agent 基于任务上下文自主决策是否调用，参考业界成熟开源 Agent 的搜索调度方案实现。
2. 明确调用决策边界，仅在必要场景触发搜索：
   - 需要时效性信息的场景：如最新技术文档、版本特性、实时报错解决方案等；
   - 涉及外部知识的场景：如第三方库 API 用法、行业标准、本地未覆盖的技术方案等；
   - 常规本地代码修改、已有文件问答、纯逻辑推理等无需外部信息的场景，禁止触发搜索。
3. 单轮任务内搜索调用次数受控，避免重复、冗余搜索，严格控制 Token 开销与执行耗时。

**验收标准**：

- 涉及外部信息的任务可自动触发搜索，无需用户手动指令；
- 纯本地代码修改、已有文件问答等场景不触发无效搜索；
- 搜索调用次数合理，无重复、冗余请求。

### 1.3 搜索过程流式可视化

**问题背景**：搜索执行过程需对用户透明，让用户感知到搜索动作与内容，同时融入现有分步输出的交互范式，不破坏对话流体验。

**需求描述**：

1. 搜索执行时，在对话流对应位置即时插入「联网搜索」工具节点，与现有工具节点视觉风格完全统一；执行中展示加载状态与当前搜索关键词简报，让用户明确知晓正在执行搜索。
2. 搜索完成后，节点内更新展示结果摘要：默认展示 3-5 条结果的精简信息（标题+核心摘要），整体内容高度受控；支持展开/折叠查看更完整的结果条目，复用现有区块折叠与二级滚动交互规范。
3. 搜索节点嵌入现有的分步输出链路中，与其他工具节点保持一致的时序与样式规范。

**验收标准**：

- 搜索执行时对话流即时出现对应工具节点，展示关键词与加载状态；
- 搜索完成后展示精简结果摘要，样式与现有工具节点统一；
- 支持展开/折叠查看详情，交互与现有区块规范一致。

### 1.4 搜索结果 Token 效率优化

**问题背景**：原始搜索结果包含大量冗余信息，直接注入上下文会造成 Token 严重浪费，需通过多层处理策略平衡信息完整性与 Token 开销。

**需求描述**：

1. **结果数量限流**：单次搜索默认返回 3-5 条高相关性结果，淘汰低权重、低相关、重复条目，从源头控制数据体量。

2. 多层过滤压缩

   ：对原始搜索结果执行三级处理，禁止无脑全量塞入消息链：

   - 清洗层：剔除广告、导航栏、页脚等无关页面元素，提取正文核心内容；
   - 摘要层：对正文内容进行语义压缩，保留核心信息点，去除冗余表述；
   - 结构化层：将结果整理为「标题+核心摘要+来源链接」的标准化结构，统一格式注入上下文。

3. **相关性淘汰**：基于任务关键词对结果做二次相关性排序，仅保留 Top N 高价值内容，避免无效信息占用上下文窗口。

**验收标准**：

- 单次搜索结果注入上下文的内容体量受控，无全量原始网页内容塞入消息链的情况；
- 结果信息完整度可支撑 Agent 完成任务，无关键信息丢失；
- Token 开销较原始全量返回显著降低，上下文窗口占用可控。

### 1.5 容错降级与全场景兼容

**问题背景**：联网搜索为辅助增强功能，必须遵循「失败不影响主功能」的底线原则，网络异常、接口故障等场景均不能阻断插件核心能力，同时需兼容所有已接入模型与运行模式。

**需求描述**：

1. **全链路异常捕获**：搜索模块全链路做异常捕获处理，覆盖网络不可用、接口请求失败、结果解析错误、无有效结果等所有异常场景；异常仅记录本地日志，不向上抛出业务异常，不中断 Agent 执行流程。
2. **优雅降级机制**：搜索失败或无有效结果时，Agent 自动回退至无搜索模式，基于已有知识与本地信息继续完成任务；仅在搜索工具节点弱标注「未获取到有效搜索结果」，无弹窗打断、无任务阻断。
3. **全模型兼容**：搜索工具作为独立工具层实现，与具体模型服务商解耦，所有已接入的 OpenAI 兼容模型均可正常使用搜索能力，无厂商限制。
4. **权限体系兼容**：搜索功能不触碰文件权限体系，对话模式、智能体模式下均可正常使用，不改变现有权限规则。

**验收标准**：

- 断网、接口异常等场景下，插件对话、Agent 执行等核心功能完全正常，无崩溃、无阻断、无强制报错；
- 搜索失败时 Agent 可正常继续作答，任务执行不受影响；
- 所有已接入的模型服务商、所有运行模式下，搜索功能均可正常调用，无兼容性问题。

## 二、代码审查与全量功能回归校验（P0 必做）

### 问题背景

搜索模块新增涉及工具调度、上下文管理、交互展示多个链路，需通过严格的代码审查与全量回归测试，确保修改不侵入现有业务逻辑，严格杜绝负向优化，同时保障交付物无隐私风险。

### 需求描述

1. 专项代码审查

   - 架构隔离性审查：确认搜索模块完全独立封装，与现有业务逻辑低耦合，不修改核心执行链路的原有逻辑；
   - 异常安全审查：确认所有网络、解析异常均有捕获，无未处理异常导致的崩溃风险；
   - 隐私安全审查：全项目与打包产物 `.vsix` 全面排查，确认无硬编码的 API 密钥、个人联系方式等隐私信息；作者署名 `wangh` 正常保留，不属于隐私范畴。
   - Token 安全审查：确认搜索结果处理逻辑符合压缩规范，无脑注入上下文的 Token 浪费问题。

2. 全量功能回归测试

   覆盖所有存量核心功能，范围包括但不限于：

   - 文本对话、多模态输入、智能体模式完整执行链路
   - 多服务商切换、模型切换、配置管理
   - 上下文 Token 统计、自动/手动压缩
   - 历史会话读写、续接、删除管理
   - 双层权限体系、安全模式切换
   - 编辑器文件修改高亮联动、右键代码注入
   - 思考链分层展示、对话滚动交互、区块折叠

### 验收标准

- 代码审查无架构耦合、安全风险与逻辑漏洞；
- 交付物无任何隐私信息，作者署名正常保留；
- 存量核心功能零回归，体验与 V1.4.5 版本完全一致。
