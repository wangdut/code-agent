# VSCode 智能编程Agent插件 V1.3.0 迭代需求规格说明书

**基准版本**：V1.2.0 

**迭代版本**：1.3.0 

**需求类型**：核心链路缺陷修复 + 配置体系语义澄清 + 质量保障专项 

**核心目标**：修复密钥重配置失效、自定义服务商新增失败两个阻断性功能缺陷；澄清设置页服务商配置项的语义边界，优化交互可读性；执行全量代码审查与功能回归测试，确保修改不引入隐性问题，所有存量成熟功能零负向优化。

## 一、核心阻断性缺陷修复（P0 最高优先级，本迭代必须闭环）

### 1.1 密钥重配置后状态同步失效修复

**问题背景**：预置服务商清除密钥后，重新填写并保存密钥，配置页显示密钥已配置，但实际发起对话时仍提示「未配置 API Key，请前往设置页配置」。根因为密钥更新后，运行时的模型适配器实例、内存中的服务商配置缓存未同步刷新，调用链路仍读取旧的空密钥状态，导致配置展示状态与实际运行状态不一致。

**需求描述**：

1. 重构服务商配置的更新通知机制：服务商密钥修改、保存成功后，主动触发运行时配置缓存刷新，同步重建对应服务商的模型适配器实例，确保新密钥即时生效，无需重启插件。
2. 新增配置状态一致性校验：每次发起模型请求前，校验内存中密钥状态与 `SecretStorage` 存储的最新状态是否一致，发现不一致时自动同步拉取最新密钥，避免缓存陈旧导致的调用失败。
3. 优化鉴权错误提示逻辑：当接口返回鉴权失败时，区分「未配置密钥」与「密钥无效/鉴权失败」两种场景，分别给出对应提示，避免状态误判。

**验收标准**：

- 清除密钥后重新填写保存，无需重启插件即可正常发起对话，无「未配置 API Key」的错误提示；
- 密钥修改后即时生效，配置页展示状态与实际运行状态完全一致；
- 鉴权失败场景提示准确，可清晰区分未配置密钥与密钥无效两种情况。

### 1.2 自定义服务商新增链路修复

**问题背景**：新增自定义 OpenAI 兼容服务商（如月之暗面）时，已正确填写官方 Base URL 与有效 API Key，仍返回「服务商不存在」错误，无法完成新增。根因为新增逻辑中残留的服务商白名单校验未完全移除，且模型拉取失败时未做错误类型拆分，统一返回笼统的服务商不存在提示，导致正常自定义服务商被错误拦截。

**需求描述**：

1. 彻底移除新增服务商环节的所有白名单、厂商名匹配校验逻辑，完全开放自定义接入能力，只要 Base URL 格式符合 HTTP/HTTPS 规范，即可进入新增流程，无任何厂商限制。
2. 重构新增流程的错误处理机制，按场景拆分精准错误提示，禁止出现「服务商不存在」类笼统提示：
   - Base URL 格式不合法：提示「接口 Base URL 格式不正确，请检查输入」；
   - 网络连接失败：提示「无法连接至接口地址，请检查网络与 Base URL 是否正确」；
   - 鉴权失败：提示「API Key 鉴权失败，请检查密钥有效性」；
   - 接口不兼容：提示「接口未兼容 OpenAI 协议规范，无法拉取模型列表」。
3. 新增降级兜底逻辑：若 `/models` 接口拉取失败，但用户已确认配置无误，支持强制完成服务商创建，用户可手动添加模型名称与元数据后正常调用，避免因接口兼容问题完全无法使用。

**验收标准**：

- 填写任意合规的 OpenAI 兼容 Base URL 与有效密钥，均可成功完成服务商新增，无白名单拦截；
- 新增失败时返回分场景的精准错误提示，无「服务商不存在」的笼统表述；
- 模型拉取失败时支持强制创建服务商，手动配置模型后可正常发起对话；
- 预置 DeepSeek 服务商的新增、编辑、调用逻辑不受影响，原有能力完全正常。

## 二、配置页服务商配置项语义澄清与交互优化（P1 高优先级）

### 问题背景

设置页模型配置栏同时存在「默认服务商」与「模型参数配置区服务商」两个下拉框，命名相似、语义边界模糊，用户无法区分二者的作用与差异，导致配置操作困惑，层级关系不清晰。

### 需求描述

1. 明确定义两个配置项的语义与作用边界
   - **全局默认服务商**：属于运行时生效的全局配置，决定插件启动、新建会话时默认使用的模型服务商，直接决定主界面默认加载的模型列表。
   - **参数编辑服务商**：属于配置页的编辑选择器，仅用于切换当前要查看、修改模型元数据的目标服务商，不影响当前运行中的默认服务商状态，也不改变会话的实际使用配置。
2. 命名与布局优化
   - 将「模型参数配置区服务商」下拉框重命名为「编辑目标服务商」，旁侧补充说明文案：「选择要查看/修改模型参数的服务商，不影响当前默认使用的服务商」；
   - 将「默认服务商」下拉框标注「全局默认」标识，补充说明文案：「新建会话默认使用的服务商，切换后主界面模型列表同步更新」；
   - 两个下拉框在布局上分区排布，增加分组标题，视觉上明确区分「运行配置」与「编辑配置」两个层级，避免混淆。
3. **联动逻辑优化** 修改全局默认服务商后，参数编辑区自动切换为对应服务商，减少用户重复操作；但编辑区切换服务商不反向修改全局默认值，保持权责分离。

### 验收标准

- 两个下拉框命名清晰，均有明确的说明文案，用户可直观理解二者作用差异；
- 布局分区明确，语义层级清晰，无操作混淆感；
- 联动逻辑合理，修改默认服务商自动同步编辑区，编辑区切换不影响默认配置。

## 三、代码审查与全量功能回归校验（P0 必做）

### 问题背景

本次修改涉及密钥存储读写、配置缓存刷新、服务商新增校验等核心底层链路，存在引入隐性缺陷、影响存量功能的风险，需通过代码审查与全量回归测试保障质量，严格杜绝负向优化。

### 需求描述

1. 全量代码审查

   ：对本次修改的所有代码执行专项审查，重点覆盖三个核心链路：

   - 密钥读写与 `SecretStorage` 交互链路，确保无敏感信息泄露、无读写逻辑错误；
   - 配置缓存刷新与适配器重建链路，确保状态一致、无内存泄漏、无并发异常；
   - 服务商新增校验与错误处理链路，确保逻辑严谨、无边界 case 遗漏。

2. 存量功能全量回归

   ：对所有成熟核心功能执行全覆盖测试，范围包括但不限于：

   - 预置 DeepSeek 服务商的对话、智能体执行全链路
   - 上下文 Token 统计、自动/手动压缩功能
   - 历史会话读写、续接、删除管理
   - 编辑器高亮联动、右键代码注入
   - 双层权限体系、安全模式切换
   - 思考链分层展示、对话滚动交互、区块折叠

3. **专项场景测试**：覆盖密钥清除与重配置、自定义服务商新增、多服务商切换三个专项场景，覆盖边界 case，确保修复效果稳定。

### 验收标准

- 代码审查无逻辑漏洞、安全风险与状态一致性问题；
- 存量核心功能零回归，体验与 V1.2.0 版本完全一致；
- 所有修复的缺陷在各边界场景下均稳定生效，无偶发异常。
