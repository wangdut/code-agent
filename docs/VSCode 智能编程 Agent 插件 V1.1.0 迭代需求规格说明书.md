# VSCode 智能编程Agent插件 V1.1.0 迭代需求规格说明书

**基准版本**：V1.0.0 **迭代版本**：1.1.0 **需求类型**：全局默认参数调整 + 多模型接入体系重构 + 设置页交互优化 **核心目标**：统一调整核心参数默认值，适配大窗口模型的主流规格，降低用户初始配置成本；彻底落地OpenAI兼容协议的多模型接入能力，取消模型列表硬编码，支持动态拉取厂商模型列表，实现主流模型服务可灵活配置接入；重构模型配置栏的UI结构与交互流程，提升配置合理性与易用性；全程不改动插件核心对话、Agent执行、交互等已有成熟功能，确保无负向优化。

------

## 一、全局默认参数统一调整（P0 最高优先级）

### 问题背景

当前模型元数据、推理参数、Agent行为的默认值与主流大窗口模型规格不匹配，无法充分发挥长上下文模型的能力，用户需手动多次调整才能适配使用场景，初始配置成本较高。

### 需求描述

对三类核心参数的默认值进行统一调整，其余无逻辑错误的配置项保持原有默认值不变，避免非必要修改影响存量体验：

1. 模型元数据默认值统一

   所有预置模型、动态拉取模型、用户自定义新增模型的默认元数据统一设置为：

   - 总上下文窗口：默认 300000 Token（展示口径为 300.0k）
   - 单轮最大输出 Token：默认 100000 Token（展示口径为 100.0k） 该值为全局默认兜底，用户可针对单个模型单独修改校准。

2. **推理参数默认值调整** 全局推理参数分组中的 `max_tokens`（单次模型请求的生成长度限制）默认值设置为 100000，取值上限受当前选中模型的最大输出Token约束。

3. **Agent行为参数默认值调整** Agent行为分组中的「最大工具调用轮次」默认值设置为 128，适配复杂长链路任务的完整执行需求。

### 验收标准

- 全新安装、初始化配置时，所有模型默认上下文窗口为300k、最大输出为100k；
- 全局推理参数 `max_tokens` 默认值为100000，最大工具调用轮次默认值为128；
- 其余原有默认参数无异常变更，不影响现有使用习惯。

------

## 二、多模型接入体系重构（P0 核心需求）

### 问题背景

当前模型列表为硬编码实现，仅支持DeepSeek两款固定模型，未真正落地OpenAI兼容协议的多模型适配能力；「新增模型」入口缺失Base URL、API Key等核心配置字段，无法接入月之暗面、智谱AI、通义千问等其他厂商的模型服务，与产品设计预期严重不符。

### 需求描述

基于原有适配器架构，补全多模型接入的完整工程能力，取消模型硬编码，实现所有符合OpenAI兼容协议的模型服务均可灵活配置接入：

1. **统一协议适配层落地** 基于OpenAI兼容接口规范完善模型适配器，统一请求格式、消息结构、流式响应、Token统计的适配逻辑，原生支持所有遵循该协议的大模型服务商接入，包括但不限于月之暗面（Kimi）、智谱AI、通义千问、DeepSeek等。

2. 模型列表动态拉取机制

   - 移除所有硬编码的模型列表，改为基于服务商配置的Base URL，调用标准 `/models` 接口自动拉取该服务商支持的全部模型列表，同步更新至本地模型配置。
   - 拉取时机：插件激活启动时自动执行一次增量同步；用户新增/修改服务商配置后立即触发拉取；支持用户手动点击刷新按钮同步最新模型列表。
   - 本地缓存机制：拉取到的模型列表本地持久化缓存，离线场景下使用缓存数据，避免每次启动重复请求。
   - 元数据兜底：接口未返回模型上下文窗口、最大输出等元数据时，自动套用全局默认值（300k上下文/100k输出），用户可手动修改校准。

3. 服务商级新增能力

   将原「新增模型」升级为「新增模型服务商」能力，支持用户按厂商维度接入服务：

   - 新增时必填项：服务商名称、接口Base URL；API Key为选填项，支持先新增服务商、查看可用模型列表，后续再补充密钥。
   - 新增完成后，自动基于Base URL拉取该服务商下的全部可用模型，纳入全局模型列表供切换使用。
   - 支持对已有的服务商配置进行编辑、删除操作，修改Base URL后自动重新拉取模型列表。

4. **默认预置配置保留** 默认预置DeepSeek服务商及官方Base URL，用户仅需填写API Key即可直接使用，保持原有开箱即用的体验；预置的DeepSeek模型列表同样改为动态拉取，自动同步官方新增的模型（如deepseek-reasoner等）。

### 验收标准

- 可通过新增服务商的方式接入任意OpenAI兼容协议的模型服务，配置完成后可正常进行对话与Agent任务执行；
- 模型列表无硬编码，新增服务商后自动拉取对应全部模型，DeepSeek官方新增模型可自动同步；
- 支持不填写API Key先完成服务商新增、查看模型列表，后续补充密钥后即可正常调用；
- 默认预置DeepSeek服务商，输入密钥后可直接使用，原有DeepSeek使用体验无衰减；
- 所有接入的模型均支持上下文统计、参数配置、模式切换等原有能力，无功能缺失。

## 三、设置页模型配置栏UI交互优化（P0）

### 问题背景

当前模型配置栏结构层级不清晰，新增模型入口缺失核心配置字段，无法支撑多服务商的管理需求，易造成用户操作困惑，与新的多模型体系不匹配。

### 需求描述

重构设置页「模型配置」分组的UI结构与交互逻辑，匹配「服务商-模型」两级体系，提升操作合理性与易用性：

1. 布局层级重构

   模型配置栏采用「服务商管理区 + 模型参数配置区」的两级结构：

   - 上层服务商管理区：展示所有已添加的模型服务商，支持新增、编辑、删除、刷新模型列表操作；每个服务商展示名称、Base URL、密钥配置状态。
   - 下层模型参数配置区：选中指定服务商后，展示该服务商下的所有模型，支持针对单个模型修改上下文窗口、最大输出Token等元数据。

2. **新增服务商弹窗优化** 弹窗内包含完整配置项：服务商名称、接口Base URL、API Key（选填，支持掩码显示与显隐切换），表单校验规则清晰，填写引导明确。

3. **配置项说明补全** 所有配置项补充tooltip说明，明确各字段的作用、填写规范与生效条件，避免用户理解歧义。

4. **全局控件联动适配** 对话底部快捷栏的模型切换下拉框同步适配多服务商模型，按服务商分组展示所有可用模型，切换逻辑与原有体验保持一致。

### 验收标准

- 模型配置栏层级清晰，服务商管理与模型参数配置分区明确，操作路径顺畅；
- 新增服务商弹窗包含所有必要配置项，支持API Key选填与掩码显示；
- 底部模型切换下拉框可正常展示所有服务商的全部模型，切换功能正常无异常。

## 四、全量功能回归校验（P1 必做）

### 问题背景

模型适配层与配置模块属于插件底层核心链路，调整范围涉及请求封装、配置管理、UI渲染多个模块，存在波及存量功能的风险，需执行全面回归验证确保功能稳定。

### 需求描述

完成上述修改后，对核心功能链路执行全量回归校验，覆盖范围包括但不限于：

- 智能体模式完整执行链路、对话模式文件问答能力
- 上下文Token统计、自动压缩、手动压缩功能
- 历史会话读写、续接、删除与列表展示
- 编辑器文件修改高亮联动、右键注入代码功能
- 双层权限体系、安全模式切换逻辑
- 思考链分层展示、对话滚动交互、区块折叠功能

校验标准：所有功能表现与V1.0.0稳定版本完全一致，无功能失效、交互异常、样式错乱、数据统计错误等问题；校验中发现的关联缺陷需同步修复闭环。

### 验收标准

- 存量核心功能零回归，体验与上一版本保持一致；
- 多模型修改仅作用于配置与模型调用层，不侵入业务功能逻辑。
