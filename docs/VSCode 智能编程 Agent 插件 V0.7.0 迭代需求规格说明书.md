# VSCode 智能编程Agent插件 V0.7.0 迭代需求规格说明书

**基准版本**：V0.6.0 

**迭代版本**：0.7.0 

**需求类型**：交互体验优化 + 对话流展示逻辑重构

 **核心目标**：优化对话输出过程中的滚动交互逻辑，平衡实时进度跟随与历史消息回看需求；重构思考链的展示结构，实现推理内容与执行节点一一对应，提升执行过程的可读性与可理解性；现有其余功能与视觉风格保持不变。

------

## 一、对话滚动交互逻辑优化（P0 最高优先级）

### 问题背景

当前对话输出过程中，滚动条强制锚定在对话底部，新内容输出时持续触发自动滚动，用户无法手动上翻查看历史消息，打断过程中的回溯查看操作；同时缺少滚动状态的智能恢复机制，无法兼顾实时进度查看与历史回溯的双重需求。

### 需求描述

重构对话区滚动控制逻辑，实现「用户干预则暂停跟随，静默超时则自动恢复」的智能滚动机制：

1. **滚动跟随自动解除**：当用户执行手动拖动滚动条、鼠标滚轮滚动等主动视口调整操作时，立即终止自动滚动跟随逻辑，保持当前视口位置不变，新内容输出时不强制跳转至底部，保障用户可自由查看历史内容。
2. **静默超时自动归位**：新增滚动静默检测机制，当用户停止所有滚动操作（无拖动、无滚轮输入）后，启动5秒倒计时；倒计时结束未触发新的滚动操作时，自动平滑滚动至当前最新输出节点位置，恢复实时执行进度展示。倒计时期间用户再次触发滚动操作则重置计时器。
3. **默认跟随规则保留**：无用户滚动干预时，对话输出始终保持自动滚动至最新内容的逻辑，默认展示当前正在执行的节点位置，确保用户可实时感知Agent当前执行进度。

### 验收标准

- 输出过程中手动拖动滚动条或滚动滚轮，可稳定停留在当前视口，不会被强制拉回底部；
- 停止滚动操作5秒后，自动平滑滚动至最新输出位置，过程无突兀跳转；
- 5秒内再次滚动则重置计时，不触发自动归位；
- 无用户干预时，新内容始终自动滚动到底部，默认展示最新执行节点。

## 二、思考链分散化分段展示重构（P0 最高优先级）

### 问题背景

当前流式分步输出模式下，全量思考链内容仍聚合在执行链路末尾集中输出，与工具调用、执行结果等节点脱节，用户无法将推理逻辑与对应执行动作关联；且思考内容无合理分段排版，内容拥挤堆叠，阅读体验差。

### 需求描述

拆解思考链的输出与渲染逻辑，实现推理内容按执行阶段分散挂载、分段排版，与执行节点深度对应：

1. **思考节点按阶段拆分挂载**：将完整推理链路按执行阶段拆分为多个独立的思考区块，分别对应任务规划、工具调用决策、执行结果分析、下一步动作推导等阶段；每个思考区块紧跟对应执行节点的前后位置，严格遵循「思考片段→工具调用→执行结果→下一段思考→下一工具调用」的时序结构，实现推理逻辑与执行动作一一对应。
2. **思考内容分段排版优化**：每个思考区块内部按语义单元自动分段，保留标准段落间距与行高，避免内容堆叠拥挤；长思考内容支持展开/折叠切换，默认完整展开。
3. **视觉样式统一**：所有分散的思考区块保持统一的视觉标识与样式规范，与现有思考过程组件风格一致，确保用户可快速识别推理内容，不破坏整体视觉一致性。

### 验收标准

- 思考内容分散对应到每一步执行动作的前后，不再集中堆积在对话末尾；
- 思考内容按语义分段清晰，段落间隔合理，无拥挤堆叠现象；
- 所有思考区块样式统一，与整体界面风格兼容；
- 执行完成后可完整回溯每一步操作对应的推理逻辑。
