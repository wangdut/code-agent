# VSCode 智能编程Agent插件 V1.1 迭代需求规格说明书
**基准版本**：V1.0（0.1.0）
**迭代版本**：0.2.0
**需求类型**：阻断性缺陷修复 + 交互体验优化 + 配置体系澄清 + 性能优化
**核心目标**：修复 V1.0 版本的功能阻断性问题，对齐桌面端交互规范，明确配置语义，提升插件整体稳定性、流畅度与可用性

---

## 一、阻断性缺陷修复（P0 最高优先级，本迭代必须闭环）
### 1.1 上下文压缩后消息协议合法性修复
**问题背景**：手动触发上下文压缩后，继续对话时模型接口返回 400 错误，报错信息为 `Messages with role 'tool' must be a response to a preceding message with 'tool_calls'`，直接导致会话不可用。
**根因约束**：OpenAI 兼容协议中，`tool` 角色消息与前序 `assistant` 消息的 `tool_calls` 为强制配对关系，不可拆分、孤立保留。
**需求描述**：
1. 重构上下文压缩模块的消息处理逻辑，严格遵循目标模型的消息协议规范，保证压缩后消息链的格式与语义双重合法。
2. 对工具调用消息对执行原子化处理规则：
   - 处于活跃对话层的工具调用轮次，必须完整保留「assistant 带 tool_calls + 对应 tool 结果」的配对结构，禁止拆分；
   - 需压缩至摘要层的工具调用轮次，将「调用请求+执行结果+最终结论」整体转化为自然语言结构化摘要，替换原配对消息，禁止单独残留 `tool` 角色消息。
3. 新增请求前置校验逻辑：每次向模型接口发请求前，自动校验消息链的角色顺序与配对关系，检测到异常时自动修正，杜绝非法请求流出。
**验收标准**：
- 手动/自动触发上下文压缩后，均可正常续聊，无 400 协议类报错；
- 包含多轮工具调用的长会话压缩后，任务链路逻辑自洽，无上下文错乱；
- 压缩后的消息结构可通过协议格式校验。

### 1.2 WebView 冷启动加载异常修复
**问题背景**：VSCode 关闭重启后首次打开插件面板，出现 WebView 加载失败、面板全灰无内容的问题，需二次开关面板才能正常渲染。
**根因约束**：插件激活生命周期与 WebView 初始化时序不匹配，扩展宿主核心模块未就绪时，WebView 提前发起数据请求，导致渲染上下文初始化失败。
**需求描述**：
1. 重构 WebView 与扩展宿主的初始化通信链路，增加就绪握手机制：WebView 渲染完成后主动发送就绪信号，待扩展宿主完成配置、存储、引擎等核心模块初始化后，再下发初始会话数据。
2. 增加加载异常兜底机制：检测到 WebView 渲染失败时，自动触发 1 次重试渲染；重试失败则展示标准化错误提示与手动刷新按钮，避免无响应灰屏。
3. 优化插件激活逻辑，非核心模块采用懒加载策略，降低激活阶段的主线程阻塞。
**验收标准**：
- VSCode 冷启动后首次打开插件面板，100% 正常渲染，无灰屏、白屏问题；
- 多次开关侧边栏、切换其他面板后再打开，均能正常加载，无状态异常；
- 异常场景下有明确错误提示与可操作的恢复入口。

## 二、交互体验优化（P1 高优先级）
### 2.1 历史会话列表交互修复与性能优化
**问题背景**：历史会话侧边栏滚动卡顿；右键呼出菜单后，重命名输入框持续处于编辑态，无法通过常规操作退出，需重复右键才能关闭菜单，不符合桌面端通用交互规范。
**需求描述**：
1. **列表性能优化**：历史会话列表采用虚拟滚动（Virtual List）方案，仅渲染视口内的条目节点，解决大量历史会话导致的滚动卡顿问题。
2. **右键菜单交互标准化**：
   - 点击面板空白区域、点击其他会话条目、按下 ESC 键时，自动关闭右键菜单并退出重命名编辑状态；
   - 重命名输入框触发后自动聚焦，失去焦点时自动提交结果并退出编辑态，ESC 键取消本次编辑；
   - 右键菜单弹出位置严格对齐鼠标坐标，无错位偏移。
3. 整体交互逻辑对齐 VSCode 原生文件树的右键交互规范。
**验收标准**：
- 百条以上历史会话时，滚动流畅无卡顿，帧率不低于 50FPS；
- 右键菜单可通过多种常规操作正常关闭，无残留编辑态；
- 重命名提交、取消逻辑符合桌面端用户直觉。

### 2.2 思考过程可视化与可回溯能力
**问题背景**：Agent 执行过程中仅展示加载动画，无推理过程输出；回复完成后思考内容直接隐藏，用户无法回溯推理逻辑，也无法感知执行进度。
**需求描述**：
1. **实时流式展示**：Agent 推理阶段（任务规划、工具调用决策、错误复盘等）流式输出思考内容，在对话流中以专属「思考区块」展示，视觉上弱于正式回复，对齐主流 Agent 插件的设计范式。
2. **永久可回溯**：回复完成后，思考区块不删除、不隐藏，保留在对话流对应位置；默认折叠展示，用户可点击展开查看完整推理过程。
3. 思考区块与正式回复、工具执行区块视觉层级清晰，不干扰主内容阅读。
**验收标准**：
- 推理过程中可实时看到流式输出的思考内容，无长时间无反馈的加载状态；
- 对话结束后思考内容永久留存，支持展开/折叠切换；
- 区块样式统一，不打断对话流阅读节奏。

### 2.3 Markdown 渲染与格式复制能力增强
**问题背景**：对话输出文本排版拥挤，段落区分度差，Markdown 语法未正确渲染；复制内容仅为纯文本，无法保留格式。
**需求描述**：
1. **全量 Markdown 渲染**：对话内容区接入成熟 Markdown 渲染引擎，完整支持标题、有序/无序列表、代码块、表格、引用、加粗、斜体等标准语法；严格遵循排版规范，段落间保留合理行间距，列表、引用块缩进合规，避免内容拥挤。
2. **代码块增强**：代码块支持对应语言的语法高亮、行号显示，右上角常驻一键复制按钮。
3. **富文本复制**：用户选中文本复制时，同时向剪贴板写入「纯文本」与「Markdown 源格式」两种内容，粘贴至支持 Markdown/富文本的编辑器时可保留完整格式。
4. 渲染样式与 VSCode 深浅色主题联动，保证不同主题下的可读性。
**验收标准**：
- 标准 Markdown 语法均可正确渲染，排版清晰，段落层级分明；
- 代码块高亮准确，复制功能可用；
- 复制内容粘贴至 Markdown 编辑器可保留完整格式。

### 2.4 底部快捷栏新增安全权限模式切换
**问题背景**：执行权限模式（询问模式/全自动模式）仅能在设置页修改，切换路径长，高频切换场景下操作效率低。
**需求描述**：
1. 在对话输入框底部快捷操作栏，与「对话模式/智能体模式」下拉框并列，新增「安全权限」下拉选择框，选项包含：
   - 询问模式：文件修改、高危终端命令执行前，必须弹出确认面板由用户确认
   - 全自动模式：工作区内文件操作、普通终端命令自动执行，无需确认
2. 切换即时生效，作用于当前会话；与全局设置双向同步：修改全局设置时下拉框同步更新，快捷切换时同步写入全局配置。
3. 控件样式、尺寸与现有下拉框保持统一，底部栏排版整齐无错位。
**验收标准**：
- 底部栏可直观查看当前权限模式，一键切换无延迟；
- 切换后立即生效，与设置页配置双向同步一致；
- 样式与现有控件统一，布局协调。

### 2.5 会话列表展开方向修正
**问题背景**：点击展开会话列表按钮时，列表向面板内部展开，挤压对话主区域，导致对话框变形，不符合侧边栏展开的交互直觉。
**需求描述**：
1. 修正会话列表展开方向，改为向活动栏方向的侧边抽屉式展开，不占用对话主区域空间，不挤压对话内容。
2. 展开/收起过程增加平滑过渡动画，对话区域尺寸不受列表展开影响，保证视图完整性。
3. 展开状态支持宽度拖拽调节，收起后完全隐藏，无残留占位元素。
**验收标准**：
- 展开会话列表不挤压、不变形对话内容区域；
- 展开方向符合侧边栏操作直觉，交互动画流畅；
- 收起后对话区域完整展示，无多余占位。

### 2.6 API 密钥输入框密文显示
**问题背景**：API Key 输入框为输入后不显示；输入过程视觉反馈弱，用户易误以为输入失败。
**需求描述**：
1. 所有 API 密钥输入框默认以密文形式展示，输入字符替换为掩码符号，与主流密码输入框体验一致。
2. 输入框右侧增加「显示/隐藏」切换按钮，用户可临时切换明文查看，默认保持隐藏状态。
3. 输入过程保留光标、输入长度变化等实时视觉反馈，消除输入无响应的感知困惑。
4. 本地存储逻辑保持不变，密钥仍以加密形式持久化，不降低安全等级。
**验收标准**：
- 默认状态下 API Key 显示为掩码，不可直接查看明文；
- 点击显示按钮可临时查看明文，再次点击恢复掩码状态；
- 输入过程有明确视觉反馈，可感知输入成功。

## 三、配置体系澄清与增强（P1 高优先级）
### 3.1 模型参数语义明确化与作用域梳理
**问题背景**：当前配置同时存在「模型独立配置的最大输出 Token」与「全局推理参数 max_tokens」，语义模糊、优先级不明确，用户无法区分二者用途，导致调参困惑。
**需求描述**：
1. **明确定义两个参数的语义与作用域**：
   - **模型元数据 - 总上下文窗口 / 最大输出 Token**：模型本身的官方能力上限，属于不可突破的边界约束，用于 Token 用量统计、自动压缩阈值计算、请求参数合法性校验，不直接控制单次生成长度。
   - **全局推理参数 - max_tokens**：单次模型请求的生成长度限制，属于用户可调节的运行时参数，用于控制单次回复的篇幅，取值不得超过当前所选模型的最大输出 Token 上限。
2. **明确优先级规则**：单次请求生效的生成长度，以全局推理参数的 `max_tokens` 为准；若该值超过当前模型的最大输出 Token 上限，则自动截断为模型上限值。
3. **配置页体验优化**：
   - 每个模型的「总上下文窗口大小」「单轮最大输出 Token」字段增加 tooltip 说明，标注为「模型官方能力参数，用于边界校验与用量统计」；
   - 全局推理参数的 `max_tokens` 字段增加 tooltip 说明，标注为「单次请求生成长度限制，不可超过所选模型的输出上限」；
   - 新增实时校验逻辑：用户设置的推理参数超过当前模型上限时，给出提示并自动修正为合法值。
4. 保留每个模型独立配置「总上下文窗口」「最大输出 Token」的能力，适配不同模型的规格差异。
**验收标准**：
- 所有相关配置项均有明确说明，用户可清晰区分两个参数的用途；
- 参数校验逻辑生效，超范围配置有提示与自动修正；
- Token 统计、自动压缩阈值计算均基于模型元数据的窗口大小，逻辑准确。

## 四、全链路性能优化（P1 高优先级）
### 4.1 整体流畅度优化
**问题背景**：插件整体操作存在卡顿感，覆盖面板切换、对话滚动、历史列表交互等多个场景。
**需求描述**：
1. **渲染层优化**：对话内容区采用虚拟滚动方案，仅渲染视口内的消息区块；长代码块、长文本默认折叠，避免一次性渲染大量 DOM 节点。
2. **数据层优化**：历史会话、配置数据采用惰性加载，非当前激活的数据不常驻内存；大体积会话记录按需读取，避免插件启动时全量 IO 加载。
3. **通信层优化**：合并 Extension Host 与 WebView 之间的批量更新消息，减少高频 `postMessage` 调用，避免阻塞主线程。
4. 针对百轮以上的长会话做专项优化，保证打开、滚动、发送操作流畅。
**验收标准**：
- 常规会话场景下，面板切换响应延迟 < 100ms；
- 百轮对话的会话滚动流畅，无明显掉帧；
- 插件冷启动到可交互时间，较 V1.0 版本降低 30% 以上。
